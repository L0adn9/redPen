 Traffic Light AI Usage Framework
 This coursework uses a Traffic Light AI Usage Framework to guide how you may or
 may not use generative AI tools (e.g., ChatGPT, Copilot, etc.). The colour assigned to this
 task indicates the level of permitted AI assistance. You are expected to follow these
 guidelines carefully and ensure all submitted work reflects your own understanding and
 academic integrity.
 Please check the assigned colour for this coursework and adhere to the corresponding
 requirements outlined below.
 ● Red - Prohibit to use use gen AI
 You must not use any generative AI tools at any stage of this assignment. All work must be
 entirely your own. Any use of AI assistance will be considered a breach of academic
 integrity.
 ● Yellow - Restricted usage of gen AI
 Limited use of generative AI is allowed for specific purposes only (e.g., brainstorming
 ideas, clarifying concepts, or language refinement). AI must not be used to generate
 substantive content for submission. You must clearly acknowledge any AI use according to
 the course guidelines.
 ● Green - Permitted to use gen AI
 You may use generative AI tools to support your work, including idea generation, drafting,
 and editing. However, you remain responsible for the accuracy, originality, and integrity of
 your submission. Proper disclosure of how AI was used is required.

 Guidelines for the Responsible Use of Generative AI (GenAI)
You may use generative AI (GenAI) tools to support learning and development in this
assignment in the following ways:
 • Concept Clarification: Using GenAI to explain general concepts related to data
 structures and algorithms, such as stacks, queues, circular queues, priority queues,
 trees/BSTs, searching, traversal, insertion, deletion, and other relevant concepts.
 • Syntax & Toy Examples: Generating isolated, small C++ code snippets to learn C++
 syntax, basic programming constructs, or generic library usage. The examples must
 not implement or be directly related to the specific functionality, data structures,
 algorithms, or problem logic required in this assignment.
 • Debugging Assistance: Using GenAI to identify syntax errors, compiler errors,
 exceptions, or generic runtime errors in code that you have written yourself. You must
 understand and verify any suggested corrections.
 • Brainstorming & Design Discussion: Using GenAI to discuss high-level ideas,
 clarify requirements, or identify possible edge cases that may need to be considered
 when designing your system. However, the final data structure selection, algorithm
 design, implementation approach, and design decisions must be your own.
 • Learning Support: Using GenAI to explain programming concepts, terminology, or
 error messages that you do not understand.
The following uses of GenAI are NOT permitted:
 • Complete or Partial Solution Generation: GenAI must not be used to generate the
 complete assignment solution or substantial portions of the C++ implementation.
 • Core Data Structure Implementation: You must not use GenAI to design or
 generate the implementation of the required data structures, including the core
 operations of stacks, queues, circular queues, priority queues, or the optional
 tree/BST.
 • Core Algorithm & Program Logic Generation: You must not use GenAI to design,
 implement, or write the core algorithms, processing logic, workflows, or decision-
 making logic required by your assigned functionality.
 • Data Structure Selection & Justification: You must make your own decisions about
 which data structure is appropriate for each task. GenAI must not be used to provide
 the final data structure selection or the justification that you submit as your own.
 • Automated Code Tracing: GenAI must not be used to generate step-by-step code
 traces, dry runs, state changes, or execution tables required for your assessment.
 • Complexity & Performance Analysis: GenAI must not be used to generate the final
 Big-O time or space complexity analysis and justification for your own
 implementation.
 • F2F Q&A Preparation as a Substitute for Understanding: Students must not use
 GenAI to generate memorised answers for the individual F2F Q&A. During the Q&A,
 students are expected to demonstrate their own understanding of their code, data
 structures, algorithms, design decisions, and individual contribution.
 • Individual Contribution: GenAI must not be used to create work that the student
 claims as their own individual contribution.

1. Background
APU is introducing a Smart Campus Parcel Collection and Delivery Management System to
manage the increasing number of parcels received for students and staff.
The campus receives parcels from different delivery companies every day. Parcels may need
to be received at the campus delivery centre, registered into the system, sorted for collection or
delivery, assigned to collection counters or delivery personnel, collected by students or staff,
and returned to the sender when necessary.
During peak periods, hundreds of parcels may be processed within a short period. The system
must therefore provide an efficient way to manage parcels and ensure that important
operational information is maintained accurately.
The system should support different operational situations, including managing parcels waiting
to be processed, managing parcels requiring different levels of attention, allocating collection
and delivery resources efficiently, recording recent staff activities, locating parcel information,
managing parcel records, and handling exceptional situations such as missing parcels,
unavailable resources, incorrect collection information and cancelled requests.
The university requires an integrated system that applies appropriate data structures and
algorithms to manage these operations efficiently.
Your team is required to develop a C++ prototype for the Smart Campus Parcel Collection and
Delivery Management System.

Task 1 – Parcel Intake, Sorting and Processing Module
This module manages parcels when they arrive at the campus delivery centre. It is responsible
for registering parcels, maintaining their information, sorting them according to their next
required action, and managing parcels waiting to be processed.
Parcel Information
• Parcel ID
• Recipient ID
• Recipient Name
• Delivery Company
• Parcel Type
• Arrival Date/Time
• Parcel Status
Possible parcel types: Standard Parcel, Large Parcel, Fragile Parcel, Document and Special-
Handling Parcel. Possible statuses include Received, Pending, Processing, Ready for
Collection, Out for Delivery, Collected, Returned, Missing and Cancelled.
Functional Requirements
1. Register a New Parcel
Allow staff to register a parcel on arrival. Assign a unique Parcel ID, record recipient and
delivery information, parcel type and arrival date/time, assign an initial status, and prevent
incomplete or duplicate registration.
2. Maintain and Locate Parcel Records
Maintain registered parcel records and allow staff to display, search for and view selected
parcels, including relevant details and current status.
3. Sort and Process Incoming Parcels
Classify and process incoming parcels according to their next required action. A parcel may be
prepared for recipient collection, assigned for campus delivery, sent for special handling,

4. Update or Remove Parcel Records
Allow appropriate parcel information to be updated when circumstances change, including

prevented.
5. Handle Exceptional Parcel Conditions

Task 2 – Parcel Service and Collection Management Module
After a parcel has been received and registered, it may require different services before the
parcel process is completed. Examples include recipient collection, campus delivery, special
handling, re-delivery and return to sender. This module manages service requests from creation
until completion, cancellation or return.
Service Request Information
• Request ID
• Parcel ID
• Recipient ID
• Recipient Name
• Service Type
• Request Date/Time
• Request Status
Possible service types: Recipient Collection, Campus Delivery, Special Handling, Return to
Sender and Re-delivery. Possible statuses: Pending, Processing, Completed, Cancelled and
Returned.
Functional Requirements
1. Create a Service Request
Allow authorised staff to create a service request for a registered parcel. Assign a unique
Request ID, associate it with an existing Parcel ID, record recipient and service information,
assign an initial status, and prevent invalid or duplicate requests.
2. Maintain Active Service Requests
Maintain active service requests and allow staff to display requests awaiting action. Requests
should be added, viewed, processed and removed when completed or cancelled.

6. Integrated System Requirement
The team must develop ONE integrated C++ prototype. The four compulsory modules must
exchange and update relevant information rather than operating as four unrelated programs.
1. Parcel arrives at the delivery centre.

3. Parcel is sorted/routed for its next action.
4. A service request is created where required.
5. An appropriate service/resource is selected.
6. A collection counter or delivery resource is assigned.
7. The parcel/service is processed.
8. Parcel and request status are updated.
9. The activity is recorded in system history.
10. The parcel is completed, collected, delivered, returned, cancelled or placed on hold/missing
 as appropriate.
