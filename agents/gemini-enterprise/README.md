# Gemini Enterprise kit: from prototype to Gemini Enterprise in one sitting

The prototype is not a separate product. It runs the **same agent instructions** that go into Gemini Enterprise, and it already
copes with the platform's unknowns. When the licence arrives:

| Step | Command / file | What it guarantees |
|---|---|---|
| 1. Prove the prompts still work | `python3 tools/test_engine.py --live` | 32 offline tests + one live audit pass |
| 2. Build the kit | `python3 tools/ge_pack.py` | [`PASTE-SHEET.md`](PASTE-SHEET.md) is regenerated byte-for-byte from what the prototype sends to Gemini; `dist/drive/RedPen/` is the Drive folder tree to upload |
| 3. App + Drive + Jira setup | `agents/audit/00-build-guide.md` §0, `agents/fix/00-build-guide.md` §0–1 | Connectors in place |
| 4. Day-1 check #13 | build Intake + Copy-paster, ask the 2nd step to repeat the module code | Decides **direct** vs **pass-through** mode |
| 5. Paste the steps | [`PASTE-SHEET.md`](PASTE-SHEET.md) top to bottom | Settings, instructions, pass-through addendum, output schema per step |
| 6. Check every test run | `python3 tools/ge_compare.py <MODULE> <ASSESSMENT>` (paste the verdict) | Contract, schema, exposure rule, and agreement with the prototype's saved run |

## The risks we already removed
- **Steps that can only see the previous step** (undocumented in Google's docs): the engine has a `--mode passthrough` that runs
  exactly that worst case with the paste-in rules from `agents/audit/fallback-pass-through.md`. Tested live on a real APU brief and
  a sample brief: both verdicts contract-clean, no copy drift.
- **Malformed JSON / wrong shape:** every step has a JSON schema (`agents/schemas/`). The prototype validates every step against
  it and retries once; all 60 saved step outputs pass. Paste the same schema into the step's output settings.
- **The model writing the wrong exposure:** `ge_compare.py` recomputes the HIGH / MEDIUM / LOW rule from the marks.
- **Which model for the Examiner:** calibrated, not guessed: Flash 7 of 7 within one grade band, Pro 5 of 7 (`docs/calibration/results.md`).
- **Drive trigger firing on a half-uploaded folder:** `dist/drive/` README says upload `brief.txt` last.
- **Run-to-run variation:** one audit can move one level (CCP: HIGH in one run, MEDIUM in another). `ge_compare.py` treats one level
  as a warning and two as a failure; for a decision that matters, run the audit twice.

## Mapping: prototype → Gemini Enterprise
| Prototype | Gemini Enterprise |
|---|---|
| `run_audit()` steps 01–06 | Workflow **RedPen Audit**: 6 Gemini Agent steps |
| `--mode direct` / `--mode passthrough` | Step inputs: any earlier step / previous step only |
| Upload in the app, or the CLI folder | Drive event trigger on `/RedPen/Assessments/`, manual trigger, monthly schedule |
| Verdict JSON returned | Drive **create file** in `/RedPen/Verdicts/` |
| `redpen_fix.run_redesign()` + Approve button | Workflow **RedPen Fix**: Condition → Redesign → **Approval** step |
| `jira_upsert()`, `send_email()`, `.ics` | Jira create/update, Gmail send, Calendar create event actions |
| `tools/redpen_insight.py` | Chat agent **RedPen Insight** over the Jira + Drive data stores |
| `OPENROUTER_API_KEY` / `GEMINI_API_KEY` | Not needed: Gemini Enterprise runs the models itself |
